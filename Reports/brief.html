MCP Tool Action Classification

Based on the repository artifacts
One-minute summary. The assignment classifies an MCP tool into exactly one of six action categories: Read, Write, Execute, Destructive, Financial, or Other. The repository uses a server-grouped, stratified train/validation/test split; a TF-IDF + balanced logistic-regression baseline; and a discriminative DistilBERT sequence classifier. On the supplied validation set, the SLM achieved 93.02% accuracy, 0.7079 macro F1, and 0.9276 weighted F1, versus 85.93%, 0.6743, and 0.8639 for the baseline. The headline improvement is meaningful but incomplete: the SLM completely missed the 15 validation examples labeled Other, so macro F1—not accuracy—is the decision metric.

The baseline explicitly uses class_weight="balanced". The current SLM training code does not apply class weights, oversampling, or focal loss. That is a limitation and likely contributes to the poor minority-class performance, especially Other. A stronger next experiment would add weighted cross-entropy or balanced sampling, tune only on validation, and report whether macro F1 improves.

Leakage controls

  • Use the supplied server-grouped splits; do not merge files or create a row-level random split.
  • Fit TF-IDF vocabulary on training text only, then transform validation; the baseline code follows this.
  • Do not use server_slug as an input feature because it can act as a server/category proxy and is not part of the SLM text.
  • Do not inspect private test labels or tune on test_unlabeled.jsonl.
  • Duplicates are a known risk. Group isolation reduces cross-server leakage, but duplicate feature rows within a split remain and should be audited before a final experiment.

Input representation and model

Prompt/input format

name: <tool name>
description: <natural-language description>
input_schema: <serialized JSON schema>

The SLM's make_text joins these three fields with newlines. Missing values become empty strings. This preserves field boundaries and exposes both natural-language intent and argument requirements. The baseline uses the same fields separated by spaces.

Selection

The model is distilbert-base-uncased, loaded with AutoModelForSequenceClassification. DistilBERT is an open pretrained encoder, well below the assignment's 3-billion-parameter limit, and its classification head makes exact-label output natural. The matching Hugging Face tokenizer converts text into token IDs; it is saved with the model for reproducible inference.

The classifier has six logits with a fixed mapping: 0 Read, 1 Write, 2 Execute, 3 Destructive, 4 Financial, 5 Other.

Length and truncation

MAX_LENGTH = 256. Tokenization uses truncation=True, so inputs longer than 256 tokens are cut off. Padding is deferred to DataCollatorWithPadding during batching. This is memory-efficient, but tail truncation can remove important schema fields from long records; a robust follow-up should measure truncation rate and test field-aware truncation or a longer context window.

Why the SLM improved—and where it failed

Why it improved: the encoder can combine name, prose, and schema cues and learn semantic patterns that word-level TF-IDF misses. The largest broad gains are in Read, Write, and Destructive F1. The SLM also makes fewer Read/Write and Read/Execute confusions than the baseline, consistent with better contextual representations.

Why the macro-F1 gain is modest: the data is strongly imbalanced, and the SLM was not class-weighted. Financial has only 22 validation examples and Other only 15; a few mistakes move their metrics sharply. The SLM predicts no Other examples correctly, while the baseline gets 5/15. The SLM's overall accuracy therefore overstates balanced performance.

Likely failure modes:

  • Execute vs Read/Write: tool names and schemas may describe an operation without clearly stating whether it causes an external side effect.
  • Financial vs Write: financial tools can look like generic create/update tools; the class is very small.
  • Other: the category is both tiny and heterogeneous, so the model has little evidence for a stable decision boundary.
  • Long-schema truncation: at 256 tokens, decisive fields may be beyond the retained prefix.

Valid, deterministic, deployable inference

tokenizer = AutoTokenizer.from_pretrained(MODEL_DIR)
model = AutoModelForSequenceClassification.from_pretrained(MODEL_DIR)
model.eval()
with torch.no_grad():
    logits = model(**tokenizer(text, return_tensors="pt",
                               truncation=True, max_length=256)).logits
label = model.config.id2label[logits.argmax(-1).item()]
